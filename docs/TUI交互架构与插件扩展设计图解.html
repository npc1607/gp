一、Pi 原生哲学：彻底剔除特化硬编码，回归通用极简

用户明确指出：[1: 主会话 (Orchestrator)] [2: 侦查员 (Scout)] [3: 研发专家 (Implementer)] 是用户自己以前为 Pi 开发的特定工作流插件产物，并非通用的 Coding Agent Harness 核心应内置的内容。

在本次重构中，gp 核心层严格对齐 Pi 源码架构：

  • 移除死板的双拼分栏与假计时器：默认状态采用优雅的单栏全宽沉浸式会话视口（Chat Viewport），绝不无故占用屏幕宽度，绝不出现没有任务却在空转计时的假 DAG 树；
  • 零内置特化角色：Harness 核心只负责模型会话推进与工具执行，任何多 Agent 协作角色（Scout/Planner/Reviewer）均通过外部插件或工作流机制动态定义；
  • 严禁低质 Emoji：全量使用工程级精致 SVG 矢量图形与等宽 Unicode 字符（▸, ▾, ✓, ✗）；
  • 核心组件原生落地：将用户截图中的可折叠工具调用与思考组（Collapsible Calls & Thoughts）作为视口的一等公民核心组件。

三、外部插件 UI 扩展架构与数据流图解 (对齐 Pi ExtensionAPI)

用户要求：“可以通过外部插件影响 UI，扩展性需要基本上和 Pi 达成一致”。在 Pi 架构中，核心 Harness 从不固化特定的工作流角色界面，而是通过提供 渲染插槽 (Render Slots) 与 挂件注入口 (Widget Injection)，让插件完全掌控展现层：

1. 外部 JS 插件调用示范 (严丝合缝对齐 Pi `ExtensionAPI`)

// 用户自己开发的插件: .gp/extensions/my_workflow.js
gp.ui.registerToolRenderer("read", {
  renderCall: function(args) {
    return "read " + args.path + (args.offset ? ":" + args.offset : "");
  },
  renderResult: function(res) {
    return res.isError ? "✗" : "✓";
  }
});

// 如果是工作流插件，通过 setStatus 动态在泳道展示，而不是 Harness 写死！
gp.ui.setStatus("workflow_step", "Scout: 正在扫描核心符号表...");

四、常用 Agent 斜杠指令集 (Slash Commands) 契约表

指令 参数 行为说明 快捷别名
/help 无 在当前会话视口打印完整的指令集、说明及快捷键指南 /?
/diff [filepath] 调用本地 Git 生成当前代码变更对比，以标准绿红高亮 Diff 呈现 /d
/clear 无 清空视口与会话内存上下文，开启全新的干净对话 /new, /reset
/model [name] 查看当前模型；提供参数时就地无缝热切换生效模型 /m
/tokens 无 打印当前会话的精确 Token 消耗明细与资费统计 /usage
/tools 无 列出当前启用的所有内置工具、MCP 远端工具与 JS 扩展工具 无
/compact [focus] 手动触发上下文滑动窗口压缩，折叠早期历史 无
/exit 无 安全释放数据库连接与后台子协程，优雅退出 TUI 界面 /quit, /q

五、核心落地推进步骤

  1. 第一步：移除硬编码角色与空跑 DAG 树：重构 internal/tui/model.go，消除写死的 [Scout] [Implementer] 选项卡与强制 35% 分栏，默认采用单栏沉浸视口。
  2. 第二步：实现 CollapsibleCalls 聚合折叠容器组件：在 internal/tui/buffer.go 增加多轮工具调用与思考组折叠状态机，默认折叠为单行摘要（▸ 7 calls · ...），按 Space 键或回车展开详情。
  3. 第三步：打通代码 Diff 生成与工具调用卡片：在 internal/agent/loop.go 对接 ToolHandler，实时将 edit 的真实变更 Diff 和 write 目标路径优雅注入渲染。
  4. 第四步：实现 Slash Commands 分发器 (internal/commands)：在输入栏拦截以 / 开头的指令并在本地瞬间执行响应。
  5. 第五步：开放外部插件 UI 渲染器注册接口 (UIRegistry)：在 Goja JS 引擎中暴露 gp.ui.registerToolRenderer，全面兼容 Pi 扩展语法。
